# Knowledge-Centered Service (KCS v6) Article Standard & Template Guide

## 1. Overview
Knowledge-Centered Service (KCS v6) is a service management methodology that focuses on knowledge as a key asset of the support organization. Rather than treating documentation as an afterthought, KCS captures, structures, and reuses knowledge directly within the incident resolution workflow.

This guide defines the content standard, structural sections, and quality criteria for all articles generated by the `ticket-to-kb-article` skill.

---

## 2. Core KCS v6 Principles

1. **Abundance:** Share knowledge broadly; capture every reusable fix, no matter how trivial.
2. **Create Value:** Solve an issue once, reuse the solution many times.
3. **Demand-Driven:** Write knowledge in response to real customer demand captured in tickets, not theoretical scenarios.
4. **Context-Sensitive:** Document issues using the customer's language and symptoms, not solely internal engineering jargon.

---

## 3. Standard Article Structure

Every knowledge base article generated must contain the following standard sections:

### 3.1 Title
- **Format:** `[Product/Service]: [Primary Symptom or Error Message] [Context/Environment]`
- **Guidelines:**
  - Must be problem-oriented and reflect what the user or technician sees.
  - Include specific error codes (e.g., `0x8004010F`, `0x8004de40`, `Event ID 1000`).
  - Keep length between 40 and 90 characters.
  - Avoid technician conclusions in the title (e.g., use "Outlook Fails to Connect with Error 0x8004010F" instead of "Fix Corrupt OAB File in Exchange Online").

### 3.2 Search Aliases / Title Variants
- Provide 4 to 6 natural language search queries.
- Include variants representing:
  - Non-technical user queries (e.g., "why won't my email load after weekend upgrade")
  - Tier-1 service desk shorthand (e.g., "outlook 0x8004010f migration fix")
  - Error code lookups (e.g., "error 0x8004010f exchange hybrid")
  - Symptoms with product names (e.g., "outlook object cannot be found error")

### 3.3 Article Metadata
- **Article ID:** Auto-generated or ITSM-assigned identifier (e.g., `KB0092101`).
- **Category:** Primary ITSM category (e.g., `Software / Email`, `Network / VPN`, `Endpoint / Hardware`).
- **Target Audience:**
  - `End-User`: Self-service resolution containing straightforward GUI steps.
  - `Tier-1 Support`: First-contact service desk staff with basic diagnostic steps.
  - `Tier-2 / Tier-3 Engineering`: Systems engineers requiring elevated administrative rights.
- **Environment:** Specific operating system, client versions, firmware levels, and cloud services.
- **Review Cadence:** 6-month or 12-month validation cycle.

### 3.4 Issue Symptoms
- Clear, observable description of what happens.
- Verbatim error messages, dialogue boxes, system notifications.
- Event Viewer logs (Log Name, Event ID, Source, Task Category, Exception Code).
- Conditions triggering the issue (e.g., occurs only after reboot, only on VPN, only when printing PDFs).

### 3.5 Root Cause Analysis
- Plain-English technical explanation of the underlying failure mechanism.
- Distinguish between symptom and cause (e.g., symptom is "VPN fails to connect"; cause is "machine authentication certificate expired while device was disconnected from corporate network").

### 3.6 Resolution Steps
- Numbered, sequential steps that guide the reader through the fix.
- Separate paths for:
  - **Graphical Interface (GUI):** Step-by-step navigation paths with exact menu and button names.
  - **Command-Line (CLI / PowerShell):** Syntactically correct commands formatted in standard code blocks.
- Highlight prerequisites (e.g., "Requires local administrator privileges").

### 3.7 Workaround (Optional)
- Documented interim workaround if the permanent resolution requires a reboot, change window, or hardware replacement.
- Clearly note limitations or security considerations of the workaround.

### 3.8 Verification
- Explicit instructions explaining how to confirm the issue is resolved before closing the ticket.
- Example: "Launch Outlook, verify status displays 'Connected to Microsoft Exchange', and confirm new emails arrive within 30 seconds."

### 3.9 Related Articles and References
- Direct links to Microsoft Learn documentation, RFCs, vendor advisories, or related internal KB articles.

## 4. KCS Content Quality Checklist (AQI)

Before an article is marked publication-ready, it is audited against the Article Quality Index (AQI):

| Criteria | Standard Requirement |
| :--- | :--- |
| **Searchability** | Title contains primary error and symptom; 4+ search aliases provided. |
| **Separation of Concerns** | Symptoms and Cause are separate sections and do not blend. |
| **Actionable Steps** | Resolution steps are numbered and tested; prerequisites are stated upfront. |
| **PII & Privacy** | Zero customer names, employee numbers, emails, or real IPs present. |
| **Audience Appropriateness** | Language matches the target audience (End-User vs Tier-2). |
| **Tone & Style** | Professional, authoritative, zero emojis, active voice. |
